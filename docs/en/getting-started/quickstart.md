# Quickstart

> **This page is the shortest path from zero to a first bot sending one pending submission.**
> The default route is [`single-host`](../architectures/single-host.md) (Compose).
> Deployment entry points for the other presets are at the end of the page. Full command and
> configuration reference: [docker.md](../platforms/docker.md) and
> [environment.md (中文)](/reference/environment.md).

---

## 0. Decide two things first

| Question | Impact |
| --- | --- |
| Do you have a public domain for HTTPS ingress? | Yes → `telegramIngress=webhook`; no → `polling` (default, no domain or certificate needed) |
| How much memory does the machine have? | 256 MiB → single bot, no `executor`; 512 MiB → two bots + `executor`; ≥1 GiB → search and the WebUI become possible |

If you are unsure which preset to pick, use the two tables in
[choose-architecture.md](choose-architecture.md).

## 1. Prepare credentials

| Credential | Where it comes from | Where it goes |
| --- | --- | --- |
| `BOT1_TOKEN` | Create the bot with `@BotFather` | `.env` or a platform secret |
| `BOT1_CHANNEL_ID` | The target channel (`@channelname` or `-100…`) | Same |
| `BOT1_OWNER_ID` | Your own Telegram user ID | Same |
| `BOT1_REVIEW_CHAT_ID` | The review group ID (fill in when review is needed) | Same |
| `PIXIV_REFRESH_TOKEN` | The Pixiv authorisation flow | Same |
| `TELEPOST_BOT1_SUBMIT_TOKEN` | Generated by `/gen_token` inside the bot | Same |

The bot must first become an administrator of the target channel, otherwise publication fails.

**Credentials may live only in `.env` or a platform secret.** Do not put them in a JSON template,
do not commit them to Git, do not paste them into a chat screenshot. Full rules in
[credentials.md (中文)](/concepts/credentials.md).

## 2. Install

### Route A: one binary (no repository clone)

```bash
deploy init mybot          # generate .env / compose / example config in place, wizard fills bot info
cd mybot
deploy doctor              # environment self-check: dependencies, config, login, network
deploy deploy              # docker compose pull/up + health check
```

The `deploy init` wizard asks for the deployment scenario: **Webhook** (you have a domain),
**mainland China + Mihomo proxy**, **Fly.io**; press Enter to keep Polling. In non-interactive
use (a pipe, CI) it stays silent and writes placeholder configuration only.

Download the binary as `deploy-<os>-<arch>` from
[Releases](https://github.com/redtidev1918/pixivflow-telepost-deploy/releases), unpack it, rename
it to `deploy`, and on Linux/macOS remember `chmod +x`. With Go 1.22+ locally you can also run
`go build -o deploy .`.

### Route B: clone the repository

```bash
git clone https://github.com/redtidev1918/pixivflow-telepost-deploy
cd pixivflow-telepost-deploy
./scripts/bootstrap.sh     # generates .env and data/pixivflow/config.json
```

On Windows do the same manually: copy `.env.example` to `.env`, and copy
`pixivflow/config/fly-two-bots.example.json` to `data/pixivflow/config.json`.

## 3. Fill in configuration

Edit `.env`; at minimum fill `BOT1_TOKEN`, `BOT1_CHANNEL_ID`, `BOT1_OWNER_ID`.
When enabling the `executor`, also fill `PIXIV_REFRESH_TOKEN` and `TELEPOST_BOT1_SUBMIT_TOKEN`.

Edit `data/pixivflow/config.json` (use `pixivflow/config/fly-two-bots.example.json` as a
reference):

1. replace the example themes `ミク` / `アークナイツ` with the tags you want;
2. adjust the cron entries in `schedules`;
3. set the plans you want to run to `"enabled": true`.

The two targets in `delivery.targets` are `/api/bot1/v1/submissions` and
`/api/bot2/v1/submissions`; `TELEPOST_API_BASE_URL` decides which machine they hit.

## 4. Start the services

```bash
./scripts/validate.sh              # config / scripts / public-repository hygiene
docker compose up -d
docker compose ps
curl http://127.0.0.1:8080/health
```

When you need public HTTPS ingress:

```dotenv
RUN_MODE=AUTO
WEBHOOK_DOMAIN=bot.example.com
WEBHOOK_URL=https://bot.example.com
```

```bash
docker compose --profile webhook up -d
```

Caddy requests certificates automatically, and each bot gets its own `/webhook/botN` path.
`RUN_MODE=AUTO` falls back to Polling when webhook registration fails.
**Do not expose 8080 directly to the internet.**

On a mainland-China network that needs a proxy:

```dotenv
SUB_URL=https://example.invalid/subscription
HTTP_PROXY_URL=http://proxy:7890
EGRESS_ALL_PROXY=http://proxy:7890
```

```bash
docker compose --profile proxy up -d
```

## 5. Verify

| Check | Command | Expected |
| --- | --- | --- |
| Services are running | `docker compose ps` | Both services `Up` (healthy) |
| Health endpoint | `curl http://127.0.0.1:8080/health` | 200, including `process_rss`, `storage.review_queue` |
| Submission API auth | request `/api/bot1/v1/health` with the token | 200 with the token; 401 without it |
| Telegram ingress | send a direct message to the bot | The bot replies |
| Review path | generate a submit token with `/gen_token` inside the bot, trigger one download manually | A pending submission appears in the review group |
| Webhook ownership (webhook mode) | `./scripts/verify-webhooks.sh` | Both bots' webhooks point at this machine |

Manual single trigger (do not wait for Cron; run it on the machine running `executor`):

```bash
pixivflow download --config /app/data/pixivflow/config.json
```
